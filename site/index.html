Language models at Android: Netrunner

Netrunner Benchmark

A research harness that seats language models at a game of hidden information and long-horizon risk — as the Runner, as the Corp, or on both sides — against a rules-based opponent or against each other. Every decision is logged with exactly what the model saw, replayable on a board viewer, and checked for honesty.

Introduction

Android: Netrunner is an asymmetric card game. The Corp installs cards facedown and protects them with ice; the Runner makes runs to break in and steal agendas. A facedown card might be a seven-point agenda or an ambush that flatlines a careless Runner, so every run is a bet placed on partial information. Games last hundreds of decisions over fifteen or more turns, which stresses long-context play, memory, risk arithmetic, and learning within a single game.

The game is also, in practice, novel to language models. Unlike chess or Go there is no large public corpus of played games to learn from, so strong play has to be produced in context — from the rules, the decklists, and the board at hand — rather than retrieved.

The harness runs on the Chiriboga engine (via DrBo6's solo-mode fork), treated as quarantined ground truth: no engine file is modified. A model occupies a seat through the same decision interface the engine's built-in AIs use, receives the official learn-to-play rules and both decklists, and answers each decision by choosing one option from the engine's own list of legal moves.

How it works

The seat. Each decision the engine asks of a seat becomes one request: the game state as that player sees it, the recent public log, and the numbered list of legal options. The model answers through a forced tool call — reasoning first, then an option index. Decisions with a single legal option resolve without a call, and multi-step actions are offered as complete actions ("play Jailbreak, then run R&D") so the model states each intention once. A model can play either side: --seat runner, --seat corp, or --seat both for model-versus-model games, each seat with its own transcript.

Honest menus. The engine's card scripts contain shortcuts written for its own AI that quietly prune a menu to the rules AI's preferred choice. The harness makes card code treat a model's seat as a human player's, so the model always receives the full legal menu a person would — while hidden information stays hidden, card searches show the searching player their own deck, and multi-card selections are answered one card at a time.

Memory. A game is one running conversation. When the transcript nears the model's context limit, the model writes a summary for its future self and play continues from that memo plus its most recent exchanges — the memo is shown in the viewer at the moment it was written. After the game, the model answers a short debrief.

  • DeterministicSeeded engine; golden games must replay byte-identically, and recorded model games re-simulate decision by decision.
  • No cheatingAn independent checker proves no state or menu a model sees contains information its player could not see.
  • ConservationAn auditor re-derives every credit and click from the log and reconciles it with the engine's ground truth.
  • Honest interfaceExactly the engine's legal options, neutrally described, for every seat.

Card pool. Games default to the System Gateway starter decks. The harness loads any engine set a deck needs (System Update 2021, Elevation, the partial Core set), and a qualification run plays every preconstructed deck before it is allowed into benchmark games: decks that crash, stall, leak information or fail the audit are refused.

Reproduce

Everything runs from harness/ with Node 22 and Playwright's Chromium. The mock model plays random legal moves and needs no API key.

cd harness && npm install
npm test                                            # typecheck + determinism
npx tsx src/cli.ts llm-game --model mock --seed 3   # keyless end-to-end game
export ANTHROPIC_API_KEY=…                          # or OPENROUTER_API_KEY
npx tsx src/cli.ts llm-game --model claude-haiku-4-5 --seed 7 --live
npx tsx src/cli.ts llm-game --seat corp --model claude-haiku-4-5
npx tsx src/cli.ts llm-game --seat both --corp-model claude-haiku-4-5 \
    --runner-model openrouter/openai/gpt-5.4-mini
npx tsx src/cli.ts run-match --games 10 --seed 1 --model claude-haiku-4-5
npx tsx src/cli.ts replay --file out/<game>      # board viewer
npx tsx src/cli.ts site --serve                     # this page, locally

The README documents every command, flag and record format.
